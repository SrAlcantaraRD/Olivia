# Add E2E Tests for Splash Screen Parent Validation Scenarios Implementation Guide

## Overview
Add end-to-end (e2e) tests using Detox to validate both scenarios of the splash screen parent validation feature in the Oliva App: (1) when parent data exists in the database, the app should navigate directly to the private zone; (2) when no parent data exists, the app should remain on the splash screen until the user manually proceeds with the setup flow.

## Implementation Strategy
High-level approach following Clean Architecture and testing best practices:
- Focus on e2e layer: Integration tests that simulate real user interactions
- Use Detox for cross-platform mobile e2e testing
- Test both happy path and edge cases
- Ensure tests are maintainable and follow project conventions

## Layer-Specific Prompts

### 1. E2E Testing Implementation
**Prompt:**
```
You are implementing e2e tests for the splash screen parent validation feature in the Oliva App. The feature checks if parent/carer information exists in the SQLite database on app launch. If data exists, navigate to the private zone (/(tabs)); if not, stay on splash screen with continue button.

Create Detox e2e tests in the tests/e2e/ directory that cover both scenarios:

1. **Scenario 1: Parent data exists**
   - Pre-condition: Database has at least one carer record
   - Expected: App launches and automatically navigates to /(tabs) (private zone)
   - Test: Verify navigation occurs without user interaction

2. **Scenario 2: No parent data exists**
   - Pre-condition: Database is empty (no carer records)
   - Expected: App stays on splash screen showing continue button
   - Test: Verify continue button is visible and tappable, then verify navigation to setup flow after tap

Technical requirements:
- Use Detox test IDs for element selection (accessibilityLabel or testID)
- Mock or reset database state between tests
- Follow existing e2e test patterns in the project
- Include proper setup/teardown for database state
- Test on both iOS and Android platforms
- Use descriptive test names and assertions

Ensure tests are isolated and don't interfere with each other. Follow the project's testing conventions from TESTING.md.
```
