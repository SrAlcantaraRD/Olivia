# Parent Setup Implementation Guide

## Overview
Implement the parent setup feature for the Oliva App, allowing users to register parent/caregiver information, child details, and select modules during the initial onboarding process. This feature follows Clean Architecture principles to ensure separation of concerns, testability, and maintainability.

## Implementation Strategy
High-level approach following Clean Architecture:
- **Domain layer**: Define entities, ports, DTOs, and use cases for parent setup business logic
- **Database layer**: Implement data persistence using Drizzle ORM and SQLite adapters
- **Hooks layer**: Create React hooks to orchestrate use cases and manage UI state
- **UI layer**: Build components following Atomic Design with HeroUI, ensuring accessibility and i18n
- **App layer**: Integrate screens using Expo Router for navigation and form flow

## Layer-Specific Prompts

### 1. Domain Layer Implementation
**Prompt:**
```
Implement the domain layer for parent setup following Clean Architecture principles.

1. Define domain entities:
   - Create `ParentEntity` extending `BaseEntitySchema` with fields: name, relationship (enum: PRIMARY/SECONDARY)
   - Create `ChildEntity` extending `BaseEntitySchema` with fields: name, birthDate (Date), diagnosis (string)
   - Create `AppSettingsEntity` for selected modules (array of module enums)

2. Define ports:
   - `IParentPort` with methods: create(parent: TParentEntity), getById(id: string)
   - `IChildPort` with methods: create(child: TChildEntity), getById(id: string)
   - `IAppSettingsPort` with methods: create(settings: TAppSettingsEntity), update(settings: TAppSettingsEntity)

3. Create DTOs:
   - `ParentSetupRequestDto` for form input validation
   - `ParentSetupResponseDto` for API responses

4. Implement use cases:
   - `SetupParentUseCase` orchestrating parent, child, and settings creation
   - Include validation and error handling with custom domain errors

5. Define enums:
   - `RELATIONSHIP_ENUM` for parent relationships
   - `MODULE_ENUM` for available app modules (CIC, STOOL_TRACKING, etc.)

6. Create mappers:
   - `ParentMapper` for Entity ↔ DTO conversion
   - `ChildMapper` for Entity ↔ DTO conversion

Follow the instruction files: domain.1.entity.instructions.md, domain.4.port.instructions.md, domain.5.use-case-schema.instructions.md, domain.8.use-case.instructions.md
```
